# Summarize Release Notes

1. Read all supplied release notes before drafting.
2. Separate verified changes into features, fixes, known risks, and required user actions.
3. Preserve product names, version numbers, dates, and severity labels exactly.
4. State that information is unavailable when the source does not establish it.
5. Return the summary in this order:
   - Release and date
   - Highlights
   - Fixes
   - Known risks
   - Required actions
6. Omit empty sections. Keep the entire summary under 300 Chinese characters unless the user requests more detail.
