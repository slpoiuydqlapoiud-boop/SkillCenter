# 质量证据引用保护设计

## 1. 背景

SkillCenter 已经能够保存质量评测、Benchmark、优化实验和发布门禁证据，并提供治理留存清理。当前清理按时间窗口删除旧证据，但优化工作项、优化实验和发布记录仍可能引用这些证据。若清理只依据时间删除，历史决策的证据链会断裂，后续无法解释某次优化或发布为何通过。

本设计把“证据仍被生命周期资产引用”纳入留存策略，使质量证据在被引用期间保持可追溯，同时保持已有留存 API 和旧调用方兼容。

## 2. 目标

1. 在预览阶段建立统一的质量证据引用索引，覆盖所有仍持久化的优化工作项、优化实验和发布门禁记录。
2. 保护被引用的评测运行、质量快照、兼容性矩阵和 Benchmark，不因时间留存策略删除。
3. 执行阶段复核引用索引指纹；预览后引用发生变化时拒绝执行，避免 TOCTOU 导致误删。
4. 引用索引读取失败时 fail-closed：不执行任何删除，并返回稳定错误码。
5. 在预览和执行结果中提供保护数量与指纹等可审计元数据，不泄露完整引用明细。
6. 保持既有构造器、接口和没有引用索引的测试/嵌入式调用方行为兼容。

## 3. 非目标

- 本增量不改变证据产生、评测算法或发布门禁判定逻辑。
- 不删除或重写已存在的优化、发布历史记录。
- 不把完整引用列表直接暴露给管理台或 API 响应。
- 本增量不扩展 post-release assessment 的独立存储模型；其现有留存语义保持不变。

## 4. 引用来源与证据类型

引用索引读取以下生命周期资产的全量历史记录，包含终态记录，因为终态记录仍承担审计作用：

| 来源 | 保护的证据 |
| --- | --- |
| 优化工作项 | `EVALUATION_RUN`、`QUALITY_SNAPSHOT`、`BENCHMARK` 的 evidenceId |
| 优化实验 | `evaluationRunId`、`qualitySnapshotId`、`benchmarkId` |
| 发布记录的 gate snapshot | `qualitySnapshotId`、`compatibilityMatrixId`；实验引用由优化实验索引间接覆盖 |

索引使用去重集合。无效的空 ID 不进入保护集合；依赖读取或解析异常不被当成“无引用”。

## 5. 数据模型

新增治理域 `RetentionProtectionSnapshot`，包含：

- `evaluationRunIds`
- `qualitySnapshotIds`
- `compatibilityMatrixIds`
- `benchmarkIds`
- `referenceCount`
- `fingerprint`

集合和对象均不可变。指纹对规范化后的 `(sourceType, sourceId, evidenceType, evidenceId)` 排序后计算 SHA-256，保证同一引用集合产生稳定结果，不受数据库返回顺序影响。

新增 `RetentionEvidenceReferenceIndex` 接口，负责读取生命周期资产并返回快照。接口实现集中处理来源映射、去重、规范化和指纹计算；留存服务不直接依赖各业务记录的字段细节。

## 6. 预览与执行流程

### 预览

1. 验证管理员权限和留存策略。
2. 构建引用保护快照；任何读取失败均抛出 `RETENTION_EVIDENCE_PROTECTION_UNAVAILABLE`。
3. 用保护集合计算质量证据、兼容性矩阵和 Benchmark 的可清理数量。
4. 将保护快照与预览 ID 绑定，并在响应中返回保护数量和指纹。

### 执行

1. 校验预览存在、未过期、策略版本一致以及幂等键。
2. 重新构建当前引用快照。
3. 当前指纹与预览指纹不一致时，抛出 `RETENTION_PROTECTION_CONFLICT`，不删除任何数据。
4. 指纹一致时使用预览冻结的集合执行删除；保护集合内的证据保持不变。
5. 执行结果返回实际删除数量、保护数量和指纹；重复执行返回同一结果。

## 7. 存储语义

`QualityEvidenceRepository` 和 `BenchmarkStore` 增加带保护集合的 `countBefore`/`deleteBefore` 重载，旧方法委托给空保护集合。

质量证据有内部关联约束：

- 被保护的质量快照按现有状态约束同时保护同 ID 的评测运行。
- 被保护的评测运行保护其快照和 case result，防止清理后状态校验失败。
- 被保护的兼容性矩阵保护矩阵本身及其引用的评测运行。

清理统计按实际“可删除”记录计算，不把受保护记录计入 eligible count 或 deleted count。

## 8. 兼容性与失败安全

- `RetentionPreview` 和 `RetentionExecutionResult` 新字段追加在记录末尾，并保留已有兼容构造器。
- `RetentionService` 的旧构造器注入空索引；Spring 全量构造器注入真实索引。
- 索引依赖不可用时，预览和执行都 fail-closed；执行路径在删除前完成复核。
- 保护冲突不降级为继续删除。
- API 仅暴露计数和指纹，不暴露内部工作项、实验或发布数据的完整引用明细。

## 9. 验证要求

至少覆盖以下场景：

1. 被工作项引用的旧评测、快照和 Benchmark 均保留。
2. 被实验引用的旧证据均保留。
3. 被发布 gate snapshot 引用的快照和兼容性矩阵均保留。
4. 未被引用且过期的证据仍按原策略删除。
5. 预览后引用集合变化时执行失败且零删除。
6. 索引读取异常时预览失败且不触发删除。
7. 旧构造器和旧 repository 方法的回归测试保持通过。
8. 管理台可显示保护数量，并能区分保护不可用与保护冲突。

## 10. 推进与回滚

实现先在内存/JDBC 共用的 repository 抽象层增加保护重载，再接入留存服务和管理台。旧构造器使用空索引保证已有单元测试和嵌入式调用方不受影响。若上线后需要回滚，保留新增字段和重载但将真实索引配置替换为空实现即可；不会改变已有证据格式。
