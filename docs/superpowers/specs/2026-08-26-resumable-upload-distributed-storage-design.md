# Resumable Upload Distributed Storage Design

日期：2026-08-26  
状态：设计待确认；本地实现已具备断点、TTL 和容量治理，真实多实例存储尚未实施

## 目标

让 Skill ZIP 的可恢复上传在多实例部署中保持同一会话语义：任一实例都能查询进度、追加下一个分片、完成或取消上传；会话 TTL、容量限制、偏移校验和失败清理必须在实例之间一致，并且不绕过现有 ZIP 安全校验、制品完整性、版本授权和审核流程。

## 当前边界

当前 `ResumablePackageUploadService` 将会话元数据保存在进程内存，将临时 ZIP 保存在实例本地文件系统。它适合本地开发，但不能在实例重启或请求负载均衡后恢复。现有 `ArtifactStorage` 面向不可变完整制品，不能直接承担分片追加、临时对象 TTL 和并发偏移 CAS，因此不扩展该端口来承载上传会话。

## 方案与选择

采用两层、显式选择的存储边界：

- Redis 保存会话元数据、当前偏移、所有者、租约/TTL、容量计数和版本号；使用 Lua 或等价原子操作完成“校验期望偏移—更新偏移—续期”的 CAS。
- S3-compatible 对象存储保存分片临时对象，键空间固定在受保护的上传前缀内；分片对象以 `uploadId/start-end` 命名，完成时按有序分片组装为本地验证文件或目标对象。
- 本地开发默认继续使用当前本地适配器；选择 Redis/对象存储后，任一依赖未配置、不可达或能力不完整都 fail-closed，禁止静默回退本地，从而避免多实例下产生分叉会话。

不选择 Redis 直接保存分片正文：在现有单包 20 MiB、活动临时空间 512 MiB 的上限下，它虽能工作，但会把大文件临时数据放入 Redis 内存，增加故障恢复、淘汰和成本风险。

## 端口与适配器

新增上传专用 `ResumableUploadStore` 端口，领域服务不再直接依赖 `ConcurrentMap` 或临时文件路径。端口至少提供：

- `create(metadata)`：原子预留会话数/字节容量并创建首个会话；
- `load(uploadId)`：读取会话快照并校验未过期；
- `append(uploadId, ownerId, expectedStart, end, total, bytes)`：以两阶段协议验证所有者/状态/偏移/总大小，写入分片并推进版本与偏移；
- `complete(uploadId)`：仅允许完整连续会话进入完成态，并返回可验证的组装输入；
- `discard(uploadId)`：幂等删除元数据和所有临时分片，释放容量；
- `cleanupExpired(now)`：按存储端 TTL 和索引清理过期元数据、分片和容量计数；
- `readiness()`：返回 `LOCAL_ONLY`、`READY`、`NOT_CONFIGURED` 或 `NOT_READY` 以及稳定 reason code。

本地适配器保留当前文件追加和会话锁语义，并将端口契约测试化。分布式适配器使用 Redis 原子脚本协调元数据，使用对象存储条件写入保存分片；对象存储引用只在适配器内部解析，不进入 API 或治理领域。

## 数据流

1. 创建请求由现有角色与文件名/大小校验保护；store 原子预留容量并写入会话元数据。
2. 分片请求先通过会话所有者校验，再由 Redis 以 `uploadId/start-end` 作为幂等键预留当前 `expectedStart`，状态为 `WRITING` 并设置短租约；对象存储随后以同一键执行条件写入并校验长度/摘要，最后由 Redis 以 reservation version CAS 提交为 `WRITTEN` 并推进 `receivedBytes`。只有最终提交成功才返回新的进度。
3. 完成请求只把完整连续会话转换为 `READY/COMPLETED`；服务将分片组装到受控临时文件，对普通 ZIP、大小、目录、扫描和 SHA-256 做现有验证。
4. 验证成功后继续调用现有制品存储、版本授权和审核提交；验证或后续治理写入失败都执行幂等 discard，不产生已发布资产。
5. 取消、过期和失败清理删除临时分片并释放分布式容量；清理失败保留受控重试/可观测状态，不伪报已清理。

## 并发、不一致与错误契约

- 同一会话只有一个连续偏移；重复的相同分片请求必须返回幂等结果，内容或范围不同返回稳定冲突码，不允许跳跃写入。
- Redis 预留成功但对象分片写入失败时，偏移不得推进，租约到期后可重试或清理；对象写入成功但最终 CAS 失败时，分片只能按同一幂等键复用或由清理任务回收，不能被后续会话读取。
- 租约到期后的恢复必须先读取并校验对应对象的长度/摘要：对象完整则只允许完成同一 reservation，缺失或不一致则释放 reservation 后重试；任何实例都不能跳过 reservation 直接推进偏移。
- Redis 不可用、对象存储不可用、租约冲突和容量耗尽分别映射为脱敏稳定错误码；响应不暴露 Redis、对象存储 endpoint、凭据引用、本地路径或分片正文。
- TTL 以 Redis 为分布式事实源；本地清理任务只能清理本地适配器，不能把本地清理成功当作分布式清理成功。

## 配置与 readiness

新增显式 `skill-center.package-upload-backend` 选择，默认 `local`；分布式模式需要 Redis key 前缀、对象存储 endpoint/bucket/prefix、凭据引用、连接/请求超时、reservation 租约和清理批量上限。所有值均有安全边界，禁止从请求参数覆盖。

平台 readiness 展示上传后端身份、元数据存储状态、分片存储状态、TTL/capacity 配置摘要和稳定 reason code，但不展示连接串、密钥、绝对路径或当前上传正文。分布式后端未达到 READY 时，创建新会话拒绝；已有会话按安全策略只允许查询/清理，不继续写入。

## 兼容与迁移

- API 路径、`UploadProgress` 字段和现有错误码保持兼容；前端无需知道存储后端。
- 默认 local 行为保持现有单机开发和测试兼容；切换到 distributed 必须通过配置和 readiness 明确完成。
- 不自动迁移现有本地内存会话到 Redis；切换前由运维停止写入并清理/放弃旧会话，避免同一 `uploadId` 在两个事实源出现。
- 本设计不宣称真实 Redis HA、S3/OBS 网络、跨区域复制、备份/PITR、容量/SLO 或密钥管理已完成；这些仍需目标环境联调和验收。

## 验证计划

- 端口契约：创建、reservation/commit 偏移 CAS、重复请求、TTL、容量释放、完成/取消幂等、清理和 readiness。
- 分布式 fake-client：两个服务实例共享同一 Redis/对象存储假实现，实例 A 创建后实例 B 继续上传并完成；并发冲突只能产生一个有效偏移。
- 故障注入：Redis 不可用、对象存储超时、CAS 冲突、孤儿分片、清理重试和凭据缺失均 fail-closed，且不泄露内部信息。
- API 回归：现有授权、ZIP 安全扫描、完整性校验、审核队列和取消接口保持不变；Web 测试、生产构建、生命周期 verifier 和 `git diff --check` 作为最终门禁。
