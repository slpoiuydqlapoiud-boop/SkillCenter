## 1. 项目概述

### 1.1 建设背景

部门内部的 AI Skill 由不同开发团队在本地创建和维护，目前需要一个统一入口完成发现、治理、分发、质量评测和运行运营分析。平台服务于华为某开发部门的内部人员，不面向互联网公众；平台不建设新的 Agent 框架，不提供网页端 Skill 编辑器、任意代码执行或在线调试，但通过受控的 Runner 抽象提供 Skill 执行和评测基础能力。

### 1.2 建设目标

建设一个轻量企业治理型 Skill 平台，形成以下闭环：

1. 维护者在本地开发标准 Skill 包，并以 ZIP 上传平台。
2. 平台自动完成结构、元数据、安全和依赖校验。
3. 审核人员完成内容、权限和安全审核。
4. 审核通过的版本进入内部技能市场。
5. 用户通过一键安装、CLI 安装或 ZIP 下载进行分发。
6. 部门 Agent/Codex 客户端或统一网关上报安装和调用事件。
7. 平台提供 Skill、团队和全局维度的数据分析及全链路审计。
8. 平台通过质量管理中心对 Skill 版本进行静态检查、受控评测和质量门禁。
9. 平台通过运行运营中心汇总调用/运行指标，支持版本效果对比和问题定位。

### 1.3 成功标准

- 部门内已纳管 Skill 可统一检索、查看、安装和治理。
- 所有发布版本均经过自动校验和人工审核，发布制品不可被覆盖或篡改。
- Skill 从上传到发布、安装、调用、废弃和下架均可追溯。
- 统计口径明确，重复事件不会造成指标虚高。
- 调用统计默认不采集提示词、输入文件、模型输出或其他业务正文。
- Skill 质量指标可追溯到规则版本、评测套件、Runner 和统计周期；Mock 指标不会伪装成生产运行指标。
- Skill 版本可在同一评测套件和相同口径下进行效果对比，结论可复现。
- 常用查询和浏览达到本任务书规定的性能、可用性与安全要求。

### 2.4 本次增量需求的产品边界

本次增量将平台从“资产管理与分发统计”升级为“Skill 全生命周期管理平台”，但不改变已有上传、校验、审核、发布、分发、通知、审计和统计接口的既有语义。新增能力通过独立模块和版本化接口接入：

- **质量管理中心**：管理静态质量指标、评测套件/用例、评测任务、结果明细、质量分和质量门禁。
- **运行运营中心**：展示调用/运行量、成功率、失败/超时率、P95 延迟、活跃版本、版本采用率、错误分布和趋势。
- **详情质量指标**：在 Skill 详情中展示当前版本质量分、评测通过率、运行成功率、P95 延迟、最近评测时间、数据来源和规则版本。
- **版本效果对比**：选择同一 Skill 的两个版本，使用相同评测套件对比质量分、通过率、延迟、错误率和采用情况；缺少同口径数据时必须明确标注不可比原因。
- **Runner 抽象接口**：核心域只依赖 `SkillRunner`、`EvaluationProvider` 和 `ObservabilityProvider` 契约；第一阶段使用 Mock 实现，后续为 OpenClaw、DeepEval、Langfuse 预留适配器边界。

### 2.5 本轮增量需求评审结论（2026-08-21）

本轮需求的核心判断是：平台不再只是“Skill 文件的目录和下载入口”，而要围绕一个 Skill 的上传、审核、发布、执行、评测、运行、对比和优化形成可追溯的生命周期闭环。新增模块必须以独立服务边界和版本化契约接入，不能侵入既有资产管理、分发、统计和审计接口。

| 需求 | MVP 产品化范围 | 核心验收口径 | 对应任务 |
| --- | --- | --- | --- |
| Skill 质量管理中心 | 静态检查汇总、评测套件/用例、异步评测任务、结果明细、质量分、质量快照和质量门禁 | 每个质量结论都能追溯到 Skill/版本、套件版本、规则版本、Runner/Provider、数据来源和时间窗口；失败、超时、取消可查询；敏感正文不落库 | QRO-004～QRO-011 |
| Skill 运行运营中心 | 脱敏运行摘要、调用/运行量、成功率、失败/超时率、P95、错误分布、趋势和版本采用率 | 生产调用与 Mock 评测严格分层；指标口径、统计窗口、更新时间和权限明确；支持按 Skill、版本、团队和窗口查询 | OPS-010～OPS-015 |
| Skill 详情质量指标 | 在详情页展示当前版本静态质量、评测通过率、运行成功率、P95、最近快照、门禁状态及证据来源 | 无数据、样本不足、快照缺失时显示明确空态；Mock 数据不能伪装为生产指标；不影响详情浏览和分发 | CMP-001 |
| Skill 版本效果对比 | 同一 Skill 两个版本的质量/运行指标对比，输出绝对值、差值、结论和不可比原因 | 仅在套件、规则、Runner 能力和统计窗口满足一致性时形成结论；数据不齐或来源不同必须明确“不可直接比较” | CMP-002～CMP-003 |
| Agent Runner 抽象接口 | 冻结 `SkillRunner`、`EvaluationProvider`、`ObservabilityProvider` 端口和标准结果；第一阶段仅实现确定性 Mock | 核心域不依赖 Agent 框架或第三方 SDK；执行仅面向已发布/已授权版本和白名单用例，具备超时、取消、权限上下文、错误码和健康检查 | QRO-001～QRO-003 |

本轮评审将新增能力拆分为“可独立交付的基础能力”和“后续外部系统接入”两层：第一阶段先完成契约、Mock 执行、质量证据、运营摘要和页面展示，保证不改变现有资产管理主链路；第二阶段再通过适配器接入 OpenClaw、DeepEval、Langfuse。版本治理同时要求 Skill 版本不可覆盖，服务端拒绝重复版本及不高于最新版本的上传，并返回稳定的 `SKILL_VERSION_CONFLICT` 错误码。

#### MVP 优先级与分阶段策略

1. **第一阶段（M7）**：先冻结 Runner/评测/观测契约，落地 Mock Runner 和异步评测状态机，确保执行边界、结果格式和故障场景可测试。
2. **第二阶段（M8）**：交付质量管理中心和质量门禁；质量证据先以可替换的持久化端口保存，不能因为无外部评测系统而阻塞开发。
3. **第三阶段（M9）**：接入脱敏运行摘要和运营聚合，建立 Mock/生产数据源隔离，再开放趋势、错误和版本采用率查询。
4. **第四阶段（M10）**：在详情页展示质量指标，并提供同口径版本效果对比；对比结论必须可复现，缺证据时只展示不可比原因。
5. **后续接入（M11 及以后）**：OpenClaw、DeepEval、Langfuse 仅按适配契约接入，不改变核心域对象和既有 API 语义；生产部署、性能压测、高可用和真实 Provider 联调另行验收。

#### 明确不属于本轮开发的范围

- 不建设新的 Agent 框架、Agent 编排器、模型路由、工具注册中心或通用沙箱。
- 不支持网页端创建、编辑 Skill 或保存 Skill 草稿；Skill 仍从本地 ZIP 上传。
- MVP 不执行任意脚本、任意上传文件或未声明外部连接，不接入生产凭据。
- MVP 不直接接入 OpenClaw、DeepEval、Langfuse 的生产实例；只交付契约、Mock 和测试桩。
- 不采集 Prompt、输入文件、模型输出、工具参数正文、代码内容、客户数据、密钥和凭据。

#### 增量交付的共同完成定义

- API、事件和 Provider Schema 已版本化，且保留既有资产管理接口兼容性。
- 质量快照、运行摘要和版本对比证据可持久化、可审计、可按保留期治理，失败时返回稳定错误码。
- 质量中心、运营中心和详情页具备加载、空态、权限拒绝、失败和 Mock/生产来源标识。
- 自动化测试覆盖权限、脱敏、幂等、故障/超时/取消、可比性、发布门禁和既有主链路回归。

### 2.6 V1.4 新需求分析与任务书回写

#### 2.6.1 需求判断

本次需求不是另起一个 Agent 产品，而是把现有 Skill 资产管理链路向后延伸到“执行—评测—运营—对比—优化”。因此平台的核心对象仍是 Skill、Skill 版本和治理证据；新增模块通过端口/适配器接入，不能改变上传、审核、发布、分发和既有统计接口的语义。

| 新增能力 | 要解决的问题 | MVP 交付边界 | 不纳入 MVP |
| --- | --- | --- | --- |
| Skill 质量管理中心 | 无法统一查看 Skill 的静态质量、评测结果和发布风险 | 规则/套件、异步评测、用例明细、质量分、不可变快照、质量门禁 | 自动修复、自动改包、在线编辑、生产级智能评审 |
| Skill 运行运营中心 | 无法知道 Skill 是否稳定、哪些版本被使用以及失败原因 | 脱敏运行摘要、成功率、失败/超时、P95、错误趋势、版本采用、来源和环境筛选 | 业务正文分析、完整 APM 替代品、自动扩缩容 |
| Skill 详情质量指标 | 详情页只有资产元数据，使用者无法判断质量 | 展示当前版本质量摘要、最近快照、门禁、数据来源和更新时间 | 公开评分、评论、无证据时的推断性评分 |
| Skill 版本效果对比 | 版本升级后的收益和回归无法量化 | 同套件/规则/Runner/窗口下比较绝对值、差值、结论和不可比原因；支持 Benchmark 证据 | 跨口径强行比较、自动发布更优版本 |
| Agent Runner 抽象接口 | 执行能力若直接绑定某个 Agent 产品，后续替换成本高 | 冻结 `SkillRunner`、`EvaluationProvider`、`ObservabilityProvider` 端口，第一阶段只实现确定性 Mock | 新建 Agent 编排框架、模型路由、工具注册中心、通用沙箱 |

#### 2.6.2 生命周期增量流程

```text
本地 ZIP 上传
  -> 校验/审核/发布（既有链路）
  -> 受控 Runner 执行
  -> 评测套件与规则计算质量快照
  -> 质量门禁与详情指标
  -> 运行摘要/Trace 脱敏采集
  -> 运营聚合与失败定位
  -> 同口径版本 Benchmark
  -> 可解释优化建议（仅人工处置）
```

每个阶段都必须保留 Skill/版本、规则或套件版本、Provider/Runner、数据来源、执行环境和时间窗口等证据引用；任何阶段都不保存 Prompt、输入输出正文、工具参数、代码内容或凭据。

#### 2.6.3 核心数据对象与接口责任

| 对象/端口 | 责任 | 关键约束 |
| --- | --- | --- |
| `SkillRunner` | 对已发布且有权限的 Skill 版本执行一次受控运行 | 白名单场景、超时、取消、权限上下文、稳定错误码；不得执行任意脚本 |
| `EvaluationProvider` | 使用评测套件/规则产出用例结果和质量分 | 结果可复现、失败可查询、Provider 异常收敛为稳定状态 |
| `ObservabilityProvider` | 提供脱敏运行摘要和 Trace 元数据 | 只允许 ID、状态、耗时、错误码和标签；不返回业务正文 |
| `EvaluationRun` / `QualitySnapshot` | 持久化评测过程与质量结论 | 不可变、可重启恢复、可保留期治理，标记 `dataSource=mock/production` |
| `RuntimeSummary` / `TraceObservation` | 支撑运营聚合与失败定位 | 事件幂等、冲突拒绝、权限隔离，支持 Runtime/MCP/LLM 上下文 |
| `Benchmark` | 保存基线/候选版本的同口径效果对比 | 记录比较条件和证据；不可比时不得生成误导性结论 |

#### 2.6.4 分阶段策略与外部适配

1. **阶段一（M7）**：先冻结端口和标准结果，使用确定性 Mock Runner 覆盖成功、失败、超时、取消和重试。
2. **阶段二（M8–M10）**：交付质量中心、运行运营中心、详情指标和版本对比；Mock 数据与生产数据严格分层。
3. **阶段三（M11 以后）**：通过适配器逐步接入 OpenClaw（执行）、DeepEval（评测）和 Langfuse（观测），每个 Provider 必须先通过契约、权限、脱敏、故障和性能门禁。

外部 Provider 不得把第三方 SDK 类型渗透到核心域；接入失败时平台应保持既有资产管理和分发能力可用，并以稳定错误码和可审计状态反馈。

#### 2.6.5 V1.4 验收补充

- 既有上传、审核、发布、分发、统计、通知和审计回归全部通过，新增模块不可改变其接口语义。
- 质量指标、运行指标和版本对比均展示来源、口径、时间窗口、更新时间和执行环境；无数据、样本不足和不可比都有明确空态。
- 评测和运行证据只保存脱敏元数据，具备权限、幂等、重试、超时、取消、保留期和重启恢复测试。
- 第一阶段 Mock Runner 结果确定性可复现且明确标记，不得伪装为生产运行数据。
- OpenClaw、DeepEval、Langfuse 仅需完成版本化契约和测试桩；真实部署、凭据、网络联调、容量压测和高可用演练单独验收。

## 3. 项目范围

### 3.1 一期范围

- 内部技能市场与 Skill 详情。
- Skill ZIP 上传、自动校验、审核和发布。
- Skill 版本管理、废弃、下架及回溯。
- 收藏、精选合集、安装记录和调用历史。
- 一键安装、CLI 安装、ZIP 下载。
- 部门 Agent/Codex 客户端或统一网关的数据接入。
- 全局、Skill、团队和个人维度统计。
- 团队、角色、分类、标签、通知、审计和平台配置。
- 内网部署、SSO、制品安全、监控、备份及恢复。
- Skill 质量管理中心、受控 Mock Runner 评测、质量门禁和评测历史。
- Skill 运行运营中心、质量/运行指标趋势和版本效果对比。
- `SkillRunner`、`EvaluationProvider`、`ObservabilityProvider` 的版本化接口及 Mock 实现。

### 3.2 一期明确不包含

- 在网页中创建、编辑或保存 Skill 草稿。
- 任意代码在线执行、网页端调试、Agent 编排、模型路由、工具注册和通用沙箱平台。
- 将 Mock Runner 伪装为真实生产运行能力，或在 MVP 中接入真实 OpenClaw/DeepEval/Langfuse 服务。
- 公开注册、互联网发布、外部分享、公开评分和评论。
- 计费、结算、商业化和收益分配。
- 基于模型的智能推荐、跨部门 Skill 联盟和多租户运营。
- 移动端原生应用；一期以部门桌面工作场景为主。

### 3.3 二期候选

- 受控在线调试与隔离沙箱。
- 基于组织和使用行为的智能推荐。
- 更细粒度的灰度发布、客户端自动升级策略和回滚编排。
- 跨部门授权交换和多租户治理。
- OpenClaw、DeepEval、Langfuse 的真实环境适配和联调。
- 生产级执行隔离、成本分析、智能推荐和更复杂的质量基准体系。

## 4. 用户、角色与权限

### 4.1 角色定义

- **普通开发者**：无需单独账号即可浏览、收藏、安装、使用 Skill，上传本地 ZIP，并查看本人记录。
- **平台管理员**：使用管理员账号管理平台配置、审核发布、质量门禁、运行运营、审计、合集和紧急下架；高风险版本的普通审核与安全复核均由平台管理员完成，但必须是两名不同人员。

产品登录界面只保留以上两种角色。维护、普通审核、安全复核和审计是平台管理员内部的操作权限/流程节点，不再作为第三种登录身份；后端保留 `maintainer`、`reviewer` 等历史请求头别名仅用于兼容既有客户端，不在前台展示或作为新的产品角色。

### 4.2 权限矩阵

| 能力 | 普通开发者 | 平台管理员 |
| --- | :---: | :---: |
| 浏览授权范围内的市场和详情 | ✓ | ✓ |
| 收藏、安装、下载 | ✓ | ✓ |
| 查看本人安装与调用记录 | ✓ | ✓ |
| 上传首版或新版本 | 授权范围 | 可代管 |
| 查看本团队统计 | ✓ | ✓ |
| 普通版本审核 | — | ✓ |
| 高风险安全复核 | — | ✓（须不同人员） |
| 紧急下架 | — | ✓ |
| 分类、标签、合集管理 | — | ✓ |
| 用户、团队和角色管理 | — | ✓ |
| 全局日志和数据导出 | — | ✓ |

### 4.3 身份与数据范围

- 仅支持部门统一 SSO，不提供本地账号和密码登录。
- 用户首次访问时按组织目录映射姓名、工号标识、部门和团队；平台只保存业务所需字段。
- 权限采用 RBAC 与团队/Skill 数据范围相结合的方式。
- Skill 可见范围支持“部门可见”“指定团队可见”“指定用户组可见”。搜索、详情、下载、内部链接和统计接口必须使用同一权限判定。
- 管理员临时提权、角色变更和数据导出必须记录审计日志。

## 5. Skill 包标准

### 5.1 标准目录

上传物为 ZIP，解压后必须只包含一个 Skill 根目录：

```text
<skill-id>/
├── SKILL.md                 # 必需：使用说明和能力文档
├── skill.json               # 可选：机器可读元数据清单
├── scripts/                 # 可选：脚本
├── references/              # 可选：参考资料
├── assets/                  # 可选：资源文件
└── mcp.json                 # 可选：MCP 依赖或连接声明
```

不得包含软链接、绝对路径、跳出根目录的相对路径、嵌套压缩炸弹、凭据文件、版本控制目录或平台禁止的可执行文件。

### 5.2 `skill.json`（如提供）

- `schemaVersion`：清单规范版本。
- `id`：部门范围内永久唯一、发布后不可更改的 Skill 标识。
- `name`、`version`、`description`。
- `ownerTeam`、`maintainers`。
- `category`、`tags`。
- `compatibility`：支持的 Agent/Codex 客户端及最低版本。
- `permissions`：文件、网络、命令、MCP、凭据等权限声明。
- `dependencies`：运行时、第三方包、MCP 服务及版本约束。
- `language`：Skill 文档和输出支持语言。
- `entry`：主说明文件，默认 `SKILL.md`。

可选信息包括图标、变更说明、输入输出示例、适用/不适用场景和相关合集建议。提供 `skill.json` 时，它是机器校验的权威来源；若其名称、版本等字段与 `SKILL.md` 头信息冲突，校验失败。未提供时，平台使用 Skill 根目录名作为 ID，并将初始版本设为 `1.0.0`。

### 5.3 版本规则

- 版本使用语义化版本 `MAJOR.MINOR.PATCH`。
- 已进入审核或发布的版本制品不可覆盖；重新提交被驳回版本时必须提升版本号。
- 自动校验失败不会创建正式版本记录，修复后可使用原版本号重新上传。
- 同一 Skill 的新版本必须由维护者或平台管理员上传。
- 发布版本保留制品哈希、上传者、审核链和完整检查报告。

## 6. 生命周期与业务流程

### 6.1 版本状态机

```text
本地开发
  → 上传/校验中
    ├─ 校验失败（仅形成上传失败记录，可修复后重传）
    └─ 待审核
         ├─ 已驳回（保留证据，修改本地包并提升版本后重传）
         ├─ 安全复核中
         │    ├─ 已驳回
         │    └─ 已发布
         └─ 已发布
              ├─ 已废弃（不再推荐，仍可按策略安装）
              └─ 已下架（禁止新安装/下载）
```

平台不存在“草稿”状态，也不在服务端保存未提交编辑内容。上传页面尚未提交的字段只存在于当前浏览器会话。

### 6.2 上传与自动校验

1. 维护者选择 ZIP，并填写平台治理字段：可见范围、维护团队、审核说明；核心 Skill 元数据不能在网页修改。
2. 平台创建上传任务，异步显示上传、解压、扫描和校验进度。
3. 系统检查压缩安全、目录结构、清单 Schema、字段一致性、唯一 ID、语义化版本、兼容性、权限声明、敏感信息、恶意文件、危险脚本和依赖风险。
4. 失败结果必须定位到文件、字段和规则，并给出可执行的本地修复建议。
5. 校验通过后生成只读预览、制品哈希、风险等级和审核任务。

### 6.3 风险分级

- **低风险**：说明性内容、只读查询、无本地写入和无高危外部连接。
- **中风险**：访问受控网络/MCP、执行受限命令、读取工作区或依赖较多。
- **高风险**：文件写入、系统命令、凭据使用、外部数据传输、生产变更或高危依赖。

风险等级由规则引擎依据声明和扫描结果计算。普通开发者不能自行降低等级；管理员调整必须说明理由并留痕。高风险版本必须经过两名不同平台管理员完成普通审核与安全复核，安全复核不新增产品登录角色。

### 6.4 审核与发布

- 审核详情展示制品树、渲染后的 `SKILL.md`、清单信息、自动检查结果、与上一发布版本的文件/元数据差异、权限变化和风险说明。
- 平台管理员可批准、驳回或转安全复核，驳回必须填写原因。
- 审核人与提交人不得为同一人；高风险版本的两名平台管理员不得相同。
- 批准后系统将制品写入不可变发布区，更新搜索索引和详情页，并向维护者发出通知。
- Skill 首个版本发布后创建市场条目；后续版本发布后默认将“最新稳定版”指向新版本，但不删除旧版本。

### 6.5 废弃与下架

- “已废弃”用于正常淘汰：详情页显示警告、推荐替代版本；是否允许继续安装由版本策略控制。
- “已下架”用于安全、合规或严重质量问题：禁止新安装、CLI 获取和 ZIP 下载；已安装客户端在下一次检查时收到升级/卸载建议。
- 紧急下架需填写原因、影响范围和处置建议，并通知维护者、已安装用户及相关团队。
- 下架不物理删除制品和历史数据，制品仅对具备审计权限的人员可见。

### 6.6 质量评测流程

1. 维护者或管理员选择已发布/已授权的 Skill 版本和评测套件，提交异步评测任务。
2. 任务记录 Runner、评测 Provider、规则版本、套件版本、发起人和数据来源；第一阶段默认使用 Mock Runner。
3. Runner 只接收经过权限校验的 Skill 版本引用和脱敏评测用例，不允许通过质量中心执行任意上传文件、脚本或未声明外部连接。
4. 管理员可通过取消接口终止排队或运行中的任务；取消采用协作式状态机，结果可持久化恢复且重复取消幂等，已完成/失败任务不被改写。
5. 评测结果统一返回通过/失败/错误/超时/取消、质量分、耗时、错误码和可脱敏的明细引用；平台持久化逐用例状态、分数、耗时、错误码和数据来源，原始业务正文默认不入库。
6. 评测完成后生成不可变 `QualitySnapshot`，可用于详情展示、质量门禁和同套件版本对比；取消任务不生成质量快照。

### 6.7 运行运营流程

- 安装/调用事件和受控 Runner 运行结果统一转换为运行摘要，进入现有去重、聚合和权限查询链路。
- 运营中心按平台、团队、Skill、版本、客户端和时间范围展示调用量、运行量、成功率、失败/超时率、P95 延迟、错误码和版本采用率。
- 所有指标必须展示统计周期、口径、数据来源（生产事件或 Mock Runner）和最后更新时间；Mock 数据不得混入生产汇总。
- 运行异常只保留标准错误码、耗时、状态和关联 ID，不采集 Prompt、业务输入、模型输出、工具参数正文或凭据。

### 6.8 版本效果对比流程

- 仅允许比较同一 Skill 的两个版本，并要求评测套件、规则版本、Runner 能力和统计窗口满足可比条件。
- 对比结果展示质量分、通过率、成功率、P95 延迟、错误率和版本采用率的绝对值与差值。
- 任一关键维度缺失、套件不同或数据来源不同，页面必须显示“不可直接比较”及具体原因，不得用空值推导结论。

## 8. 分发与客户端集成

### 8.1 分发方式

- **一键安装**：网页生成短期、一次性、绑定用户与 Skill 版本的安装授权，唤起已注册的部门 Agent/Codex 客户端；无法唤起时回退为 CLI 指引。
- **CLI 安装**：用户复制平台生成的命令；CLI 使用 SSO/设备凭证请求安装清单和制品。
- **ZIP 下载**：用于其他兼容 `SKILL.md` 规范的工具手动导入；同样执行权限、版本状态和审计校验。

### 8.2 安装协议要求

- 默认安装最新稳定版，用户明确选择历史版本时必须提示兼容性和支持状态。
- 安装清单包含 Skill ID、版本、哈希、下载地址、有效期、依赖、权限和兼容性。
- 下载地址为短期签名地址，不允许跨用户长期转发。
- 客户端在安装前复核制品哈希和兼容性，安装结果上报平台。
- 下架版本不能获取新的安装授权；已生成但未使用的授权应失效。

### 8.3 Skill Runner 与评测适配接口

质量和运行模块采用端口/适配器设计，核心业务不依赖任何 Agent 框架或第三方 SDK：

```text
SkillQuality/Operations API
        │
        ├── SkillRunner             # 受控执行 Skill 版本
        ├── EvaluationProvider      # 计算评测分数和明细
        ├── ObservabilityProvider   # 接收脱敏运行摘要/追踪引用
        └── TraceProvider           # 查询脱敏 Trace 元数据和失败定位证据
                │
        MockRunner / MockEvaluationProvider / MockObservabilityProvider
                │
        后续适配：OpenClaw / DeepEval / Langfuse
```

- `SkillRunner` 至少包含 provider 标识与版本、能力声明、健康检查、执行请求和标准化执行结果；请求必须绑定 Skill 版本、评测任务、超时和权限上下文。
- `EvaluationProvider` 至少包含套件/规则版本、用例执行、分数聚合、明细脱敏和可比性声明。
- `ObservabilityProvider` 只接收运行 ID、Skill/版本、状态、耗时、错误码、统计标签和可选外部追踪引用，不接收业务正文。
- `TraceProvider` 只返回 Trace/Span ID、Skill/版本、操作、状态、耗时、错误码、数据来源和时间；查询必须支持窗口、Skill、版本、Trace、状态和来源过滤，并拒绝业务正文、工具参数和凭据字段。
- 运行摘要通过 `RuntimeSummaryRepository` 存储端口接入；默认使用 JSON 原子文件实现，部署环境可显式切换 Redis Hash（事件内容）与 Sorted Set（发生时间索引）实现。所有实现必须保持事件 ID 幂等、冲突拒绝、按发生时间查询、保留期删除和脱敏边界；Redis 未启用时不要求本地具备 Redis 服务。
- Mock 实现必须确定性、可重复、可注入故障，用于开发、演示和回归测试；其结果必须带 `dataSource=mock`。
- 后续真实适配器只能通过契约接入，不能改变 `SkillVersion`、`EvaluationRun`、`QualitySnapshot` 和既有分发接口的语义。
- M11 的外部适配字段、错误、密钥引用、健康状态和接入门禁详见 [Provider 适配契约](2026-08-12-provider-adapter-contracts.md)。

## 9. 安装与调用数据统计

### 9.1 安装事件

记录字段：事件 ID、Skill ID、版本、用户标识、团队、客户端类型/版本、匿名设备标识、动作类型、安装方式、发生时间、接收时间、结果和错误码。

动作类型包括安装、升级、降级、卸载；ZIP 下载作为独立下载事件，不计入安装成功。

### 9.2 调用事件

记录字段：事件 ID、Skill ID、版本、调用时间、接收时间、调用方用户/团队、客户端类型/版本、匿名会话标识、成功/失败/取消/超时、执行耗时、标准错误码，以及经批准后可选的模型和 Token 用量。

平台默认禁止采集：提示词、对话正文、输入文件内容、模型输出、工具参数正文、代码内容、客户数据、密钥和凭据。上报接口对禁止字段进行 Schema 拒绝或丢弃，并记录安全告警。

### 9.3 上报可靠性

- 客户端或网关使用平台签发的身份凭证，事件必须带唯一 ID。
- 服务端以“上报主体 + 事件 ID”幂等去重。
- 支持客户端离线缓存、批量上报、指数退避重试和服务端部分成功响应。
- 使用发生时间进行业务统计，保留接收时间用于延迟和补报诊断。
- 统计时区统一为 Asia/Shanghai，日界线为北京时间 00:00。

### 9.4 指标口径

| 指标 | 定义 |
| --- | --- |
| 已发布 Skill 数 | 当前至少存在一个未下架发布版本且用户有权查看的去重 Skill 数。 |
| 累计安装次数 | 成功的首次安装事件数；升级和降级分别统计，不混入该指标。 |
| 当前安装数 | 按“用户 + 匿名设备 + Skill”取最后状态后仍为已安装的数量。 |
| ZIP 下载次数 | 通过权限校验并完成响应的 ZIP 下载事件数。 |
| 调用次数 | 去重后、通过 Schema 校验的调用事件数。 |
| 活跃用户数 | 统计期内至少成功调用一次的去重用户数。 |
| 调用成功率 | 成功次数 ÷（成功 + 失败 + 超时）；用户主动取消不进入分母，需单列。 |
| P95 耗时 | 统计期内有效调用耗时的第 95 百分位。 |
| 版本采用率 | 某版本当前安装数 ÷ 该 Skill 全部版本当前安装数。 |

### 9.5 数据保留建议

- 调用明细默认保留 180 天，安装/下载明细默认保留 1 年。
- 脱敏日汇总默认保留 3 年，审批和管理审计日志至少保留 3 年。
- 若部门安全或审计制度要求更长/更短期限，平台配置只能在获授权情况下调整，并记录变更。
- 用户个人页面仅展示本人数据；团队和全局明细导出受角色和审批控制。

### 9.6 质量与运行指标口径

| 指标 | 定义 |
| --- | --- |
| 静态质量通过率 | 当前版本通过平台结构、元数据、安全和依赖校验的规则项数 ÷ 应校验规则项数。 |
| 评测通过率 | 同一评测套件中状态为通过的用例数 ÷ 已完成用例数；错误、超时单独展示。 |
| 质量分 | 按已发布规则版本对静态质量、评测结果和运行稳定性加权计算的 0–100 分；必须保存权重和规则版本。 |
| 运行成功率 | 受控 Runner 或生产调用中成功次数 ÷（成功 + 失败 + 超时）；取消单独统计。 |
| 运行 P95 | 同一统计窗口、Skill/版本和数据来源下有效运行耗时的第 95 百分位。 |
| 版本效果差异 | 两个版本在相同套件、规则、Runner 和窗口下的指标差值；不满足条件时返回不可比原因。 |
| 质量门禁状态 | 版本是否满足配置的最低质量分、通过率、成功率、P95 和高风险规则要求。 |

质量指标与生产运营指标必须区分数据来源、时间窗口和计算版本；Mock 结果仅可进入 Mock 看板或明确标注的评测快照。

## 11. 逻辑架构与接口边界

### 11.1 逻辑组件

1. Web 门户：市场、个人工作台、审核和治理后台。
2. API 服务：身份、目录、Skill、版本、审核、分发、收藏和配置。
3. 上传与校验服务：隔离解压、Schema 校验、安全扫描和风险计算。
4. 制品服务：不可变对象存储、哈希校验和短期下载授权。
5. 搜索服务：权限感知的全文索引和筛选聚合。
6. 事件接入服务：安装/调用批量上报、鉴权、Schema 校验和去重。
7. 统计服务：流式/批量聚合、指标查询和权限控制。
8. 审计与通知服务：关键操作留痕、站内通知和可选消息适配。
9. 质量服务：静态质量汇总、评测套件、异步评测、质量快照、门禁和版本对比。
10. 运行运营服务：运行摘要接入、质量/运行聚合、运营看板和异常分析。
11. Runner 适配层：`SkillRunner`、`EvaluationProvider`、`ObservabilityProvider` 及 Mock/外部适配器。
12. 外部适配：部门 SSO、组织目录、安全扫描、Agent/Codex 客户端、监控告警及后续 OpenClaw/DeepEval/Langfuse。

### 11.2 核心接口域

- 身份与权限：SSO 回调、当前用户、团队和权限查询。
- 市场：搜索、列表、详情、版本和合集。
- 上传治理：上传任务、校验结果、审核、发布、废弃和下架。
- 分发：安装授权、安装清单、ZIP 下载和版本状态检查。
- 事件：安装/调用批量上报、补报和接收结果。
- 统计：平台、Skill、团队和个人指标查询及受控导出。
- 质量：质量摘要、评测套件/用例、评测任务、结果、质量快照、门禁和版本对比。
- 运行运营：运行摘要、趋势聚合、错误分析、版本采用和数据来源查询。
- Runner：Provider 注册/能力查询、健康检查、受控执行和标准化结果；核心 API 不暴露第三方 SDK。
- 系统：通知、分类标签、审计和配置。

所有写接口要求鉴权、授权、幂等标识和审计；上传、下载、事件上报与导出接口还需独立限流。

## 12. 安全与合规要求

- 部署在部门认可的内网环境，全链路 HTTPS，密钥由企业密钥系统托管。
- SSO 登录、最小权限、职责分离；平台管理员不能自审，高风险必须由两名不同管理员审核。
- ZIP 在隔离工作目录解压，限制文件数、单文件大小、总解压体积、压缩比和处理时长，防止路径穿越与压缩炸弹。
- 制品执行恶意文件、敏感信息、危险脚本、许可证和依赖风险扫描；扫描引擎升级后可触发存量复扫。
- 发布制品内容寻址或强哈希校验，并在不可变存储区保存；任何元数据治理变更不改变制品内容。
- 下载和安装授权短期有效、绑定主体；禁止通过可猜测永久地址访问制品。
- 日志、事件和导出数据脱敏；禁止将密钥、正文内容和个人敏感业务数据写入日志。
- 防护常见 Web 风险：CSRF、XSS、SQL 注入、越权、重放、批量枚举和恶意上传。
- 关键行为留痕：上传、审核、发布、权限变更、下载、导出、废弃、下架、策略变更和审计查询。
- 安全事件支持按 Skill、版本、用户和团队定位影响范围，完成紧急下架与通知。
- Runner 仅允许执行已发布/已授权版本和受控评测用例，必须有超时、资源上限、权限上下文和可取消状态；MVP Mock Runner 不接触生产凭据和任意脚本。
- MVP 提供受控执行 API `POST/GET /api/v1/admin/runner/executions`，只接受已发布版本和白名单场景，返回标准化执行结果并写入脱敏运行摘要与审计；后续 Agent Runtime/MCP 服务身份通过同一端口接入。
- 评测用例、结果和外部追踪引用按业务数据分级、脱敏和保留策略管理；质量页面只展示授权范围。

## 13. 非功能要求

### 13.1 性能与容量基线

- 市场搜索 P95 不超过 1 秒；普通页面和查询接口 P95 不超过 2 秒。
- 安装授权接口 P95 不超过 1 秒；制品下载首字节 P95 不超过 2 秒，不含客户端网络传输完成时间。
- 上传和安全扫描采用异步任务，不以普通页面 2 秒指标衡量，但必须实时展示阶段和最终结果。
- 一期容量验证基线：3,000 名用户、2,000 个 Skill、20,000 个版本、日均 100 万调用事件、峰值 300 次事件写入/秒、300 个并发在线用户。
- 质量评测和版本对比采用异步任务；任务提交接口 P95 ≤ 1 秒，状态查询 P95 ≤ 1 秒；单评测任务必须有超时与失败可重试/可定位结果。
- 运营看板查询 P95 ≤ 2 秒；质量快照和对比结果必须可按 Skill、版本、套件和时间窗口分页。

### 13.2 可用性与恢复

- 核心浏览、分发和事件接入月度可用性目标不低于 99.9%。
- 元数据和配置每日备份并具备增量恢复；制品存储启用冗余和完整性巡检。
- 建议恢复点目标 RPO 不超过 15 分钟，恢复时间目标 RTO 不超过 4 小时。
- 外部扫描或通知服务异常不得阻塞市场浏览；扫描异常时禁止未经检查的版本发布。

### 13.3 可观测性

- 监控请求量、错误率、P95/P99 延迟、队列积压、扫描耗时、事件拒绝率、下载失败和存储容量。
- 关键链路使用关联 ID；告警包含影响范围、最近变更和处置入口。
- 指标、日志和追踪数据遵循同一脱敏规则。

### 13.4 兼容性与可访问性

- 支持部门标准桌面环境中的 Chrome、Edge 最新两个主版本。
- 1440px 宽度为最佳展示；1280px 及以上保持完整功能，低于 1280px 可重排但不建设独立移动体验。
- 关键流程可用键盘完成；焦点清晰；表单错误与状态变化不能仅依赖颜色。
- 正文和背景对比度目标不低于 4.5:1，常规可点击区域建议不小于 40×40px。

## 14. 视觉与交互规范

### 14.1 设计基线

- 延续效果图的企业工作台风格：浅灰蓝页面背景、白色卡片、蓝色主操作、轻边框和克制阴影。
- 建议基础色：主色 `#2869F6`、成功 `#12B76A`、警告 `#FF8A00`、危险 `#F04438`、主文字 `#101828`、次文字 `#667085`、背景 `#F7F9FC`、边框 `#E4E7EC`。
- 字体优先使用企业许可的 Huawei Sans，回退为 PingFang SC、Microsoft YaHei 和系统无衬线字体。
- 桌面布局建议：64px 顶栏、240px 左侧导航、24px 内容边距；卡片圆角 12px。
- 市场在 1440px 使用四列卡片；空间不足时降为三列。详情页主内容与右侧操作/元信息按约 8:4 分栏。

### 14.2 状态反馈

- 上传、扫描、审核和导出等异步任务必须展示阶段、进度、耗时和可重试状态。
- 危险操作使用二次确认，并明确影响版本、已安装用户数量和不可逆后果。
- 空页面必须解释原因并提供下一步；无搜索结果应允许清除条件。
- 403 区分“未登录”“无角色”“无数据范围”；不得通过错误文案泄露受限 Skill 的存在。
- 风险级别同时使用文字、图标和颜色，不能只依赖颜色。

## 15. 通知规则

站内通知为一期必选；若部门已有邮件或企业消息接口，可通过适配器同步发送，但不影响核心验收。

必须通知的事件包括：

- 上传校验完成或失败。
- 审核通过、驳回、转安全复核或超时待办。
- 新版本发布、维护关系变更。
- 已安装 Skill 出现新稳定版、被废弃或紧急下架。
- 高风险扫描发现、存量复扫状态变化。
- 角色、团队范围和平台关键策略变化。

## 16. 验收标准

### 16.1 核心业务验收

1. 未登录用户访问任意业务页会进入 SSO；无权限用户不能通过搜索、直链或下载地址获知受限内容。
2. 合规 ZIP 可完成上传、异步校验并进入待审核；网页不能修改包内核心元数据。
3. 路径穿越、压缩炸弹、缺失必需文件、字段冲突、敏感凭据或危险依赖会被拦截，并返回明确错误。
4. 平台管理员不能审核自己提交或本人团队提交的版本；高风险版本未完成两名不同管理员审核不能发布。
5. 已发布版本的 ZIP、哈希和核心元数据不可覆盖；新版本必须使用更高语义化版本号。
6. 市场搜索、筛选、排序、详情、版本历史、收藏和合集在授权范围内工作正常。
7. 一键安装、CLI 和 ZIP 下载均校验身份、可见范围、版本状态和短期授权，并产生审计/分发事件。
8. 已下架版本无法获取新安装授权或下载；详情和已安装客户端获得明确处置提示。
9. 相同事件 ID 重复上报不会重复计数；离线补报按发生时间进入正确统计周期。
10. 任何调用事件包含提示词、输出正文、文件正文或凭据字段时会被拒绝或清除并告警。
11. 平台、Skill、团队和个人看板与本任务书的指标口径一致，跨权限导出被阻止。
12. 上传、审核、发布、权限变更、下载、导出、废弃和下架均能在审计日志追溯主体、对象、时间和结果。
13. Mock Runner 能对已授权版本执行受控评测，并输出确定性的标准化执行结果。
14. 质量管理中心展示静态/动态指标、数据来源、规则/套件/时间窗口和质量门禁状态。
15. 运行运营中心展示调用/运行量、成功/失败/超时、P95、版本采用和错误趋势，并带权限、数据来源和执行环境标识；支持按 Runtime、MCP Server、LLM Provider 筛选。
16. Skill 详情展示质量指标和版本对比入口；无数据或不可比时明确说明原因。
17. 相同套件、规则、Runner 和窗口下的版本对比可复现；条件不一致时标记不可比并说明缺项。
18. Provider 契约测试覆盖 Mock 实现、健康检查、超时/失败/取消和标准结果；核心业务不依赖第三方 SDK。
19. 现有上传、审核、发布、分发、统计和审计回归不受新增模块影响。
20. 优化建议只能引用质量快照和脱敏运行聚合，输出严重度、证据和推荐动作；无数据/样本不足明确提示，不能自动修改、发布或执行 Skill。
21. 优化建议支持管理员人工处置（待处理、已确认、已忽略、已解决），处置状态按 Skill/版本/建议 ID 持久化并写入审计链；开发者只能查看建议和状态。
22. 优化建议阈值（最低成功率、最大 P95、最小运行样本）可由管理员配置并持久化，非法范围拒绝；阈值变更写入审计链，默认值可回退。
23. 管理员可提交基线/候选版本 Benchmark；系统复用相同套件、规则、Runner、窗口和数据来源计算效果，持久化对比证据及改进、回归、混合、无变化或不可比结论，开发者可只读查询。
24. Skill 详情质量页展示最新 Benchmark 结论和差值；回归或混合结论可生成带 Benchmark 证据的优化建议，但不自动执行 Skill、修改包或发布。
24a. 管理员处置优化建议时可关联 `EVALUATION_RUN`、`QUALITY_SNAPSHOT` 或 `BENCHMARK` 证据；服务校验证据存在、评测已完成（如适用）以及 Skill/版本一致性，仅持久化受控证据类型和 ID 并写入审计。`NONE` 证据保持向后兼容；不得保存 Prompt、输入输出、工具参数或凭据。
25. 运行运营中心支持管理员查询脱敏 Trace 元数据并定位失败/超时；支持窗口、Skill、版本、Trace、状态和数据来源筛选，开发者无权访问，响应和页面不得出现业务正文。
26. 运行摘要和 Trace 证据跨服务重启可恢复，按事件 ID 幂等写入；保留期预览/执行包含运行摘要删除数量，过期证据删除有审计记录，持久化失败返回稳定错误。
27. 审核发布前读取目标版本最新质量快照；存在 `BLOCKED` 快照时返回 `QUALITY_GATE_BLOCKED` 及门禁原因并保持待审核状态；无质量证据时兼容既有发布链路。
28. 评测运行、质量快照、评测套件和当前规则通过 `QualityEvidenceRepository` 持久化并在重启后恢复；Provider 异常只落为稳定失败状态，不保存异常正文；写入失败返回 `QUALITY_EVIDENCE_PERSISTENCE_FAILED`。
28a. 评测请求、评测运行、质量快照和 Runner 请求可携带受控的 `runtimeId`、`mcpServerId`、`llmProviderId`；仅允许有限长度标识，旧数据缺失时按空值兼容，任何 Prompt、凭据、工具参数和业务正文均不得进入这些字段。
29. 质量运行和快照按调用保留期纳入 RetentionService 预览/执行；删除数量进入执行结果和审计，评测套件与当前规则不被删除，管理页展示质量证据清理数量。

## 21. 关键风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| Skill 包格式不统一 | 上传失败率高、迁移成本大 | 提供 Schema、示例包、本地预检工具和清晰错误码。 |
| 客户端版本碎片化 | 一键安装或统计不一致 | 建立兼容矩阵、最低版本门禁和协议版本字段。 |
| 调用事件重复或补报延迟 | 看板数据失真 | 唯一事件 ID、幂等去重、发生/接收时间分离和迟到数据重算。 |
| 高风险 Skill 审核不足 | 安全和生产风险 | 规则风险分级、双人审核、存量复扫和紧急下架。 |
| 统计采集业务正文 | 隐私与合规风险 | 白名单 Schema、服务端拒绝未知正文、脱敏审计和采集指南。 |
| 搜索索引泄露受限条目 | 权限越权 | 写入可见范围、查询时二次授权、直链和联想词统一鉴权。 |
| 已安装版本下架后失联 | 风险持续存在 | 客户端周期检查、影响清单、强通知和升级/卸载建议。 |
| Mock 与生产指标混淆 | 运营判断失真 | 所有结果带 `dataSource`/Provider/规则版本，Mock 看板与生产运营看板分离。 |
| 评测样本包含敏感业务数据 | 隐私与合规风险 | 使用脱敏合成样本，限制访问和保留期，禁止保存输入/输出正文。 |
| Runner 与第三方 SDK 耦合 | 后续替换成本高 | 采用端口/适配器和契约测试，核心域只依赖标准接口。 |
| 执行资源或权限滥用 | 服务稳定性和安全风险 | MVP 不执行任意脚本，使用 allowlist、超时、资源上限、权限上下文和可取消状态。 |

## 22. 结论

本项目在保留资产治理、审核、分发和统计能力的基础上，增量升级为 Skill 全生命周期管理平台：新增质量管理、受控评测、运行运营、详情质量指标和版本效果对比，并通过 Runner/评测/观测适配接口为 OpenClaw、DeepEval、Langfuse 预留接入位置。MVP 只使用确定性的 Mock Runner，不建设新的 Agent 框架、不提供在线编辑或任意代码执行。所有后续 UI、技术方案和实施计划均应遵守“可治理、可评测、可运营、可审计”的边界。
