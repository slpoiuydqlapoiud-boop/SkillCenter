# Skill Artifact Storage Abstraction Design

日期：2026-08-25  
状态：平台侧实施中；真实对象存储适配与目标环境验收仍开放

## 目标

把 Skill 制品的上传、身份验证、目录读取、Manifest 元数据和下载资源统一收敛到可替换的 `ArtifactStorage` 端口，避免领域服务直接依赖本地文件路径，为生产对象存储迁移保留稳定边界。

## 设计

- `ArtifactStorage` 提供写入、校验元数据和打开资源三个能力；调用方只持有 opaque artifact reference，不解析存储根目录。
- 默认本地适配器以 SHA-256 内容寻址：写入到 `sha256/<digest>.zip`，通过临时文件和原子移动发布；相同摘要的有效制品幂等复用，已有摘要对应的损坏制品拒绝覆盖。
- 新上传返回 `local://sha256/<digest>.zip` 引用。旧 JSON 中的绝对路径、相对路径和空引用继续按兼容规则读取；新链路不把绝对路径返回 API 或写入新增领域元数据。
- Manifest、下载和上传后的目录读取均经统一校验：普通文件、非符号链接、可读 ZIP、记录 SHA-256；失败时 fail-closed，不消费授权，不生成替代制品。
- 对象存储不在本地伪造实现。未来适配器必须实现同一端口，并在未配置、不可达或校验失败时返回稳定不可用状态。

## 兼容与安全边界

- `SkillVersion.artifactPath` 字段暂不改名，保留历史 JSON 反序列化和生命周期哈希兼容；其新值语义为 opaque reference，旧值由本地适配器兼容解析。
- 不在日志、错误响应、审计元数据或 readiness 响应中暴露本地绝对路径、制品正文或上游存储异常。
- 上传验证完成后才写入内容寻址制品；治理记录写入失败时不把未登记制品当作已发布资产。

## 验证

- 单元测试覆盖内容寻址写入、重复摘要幂等、损坏目标拒绝覆盖、opaque 引用解析、历史路径兼容和统一完整性失败。
- API 回归覆盖真实上传后的目录/Manifest/下载路径和授权不消费边界；Web、生命周期 verifier 和 `git diff --check` 继续作为最终门禁。

## 生产边界

本设计不宣称真实 S3/OBS、签名 URL、跨区域复制、保留策略、备份/PITR、容量/SLO 或密钥管理已经接通；这些仍需目标环境适配、联调和验收证据。
