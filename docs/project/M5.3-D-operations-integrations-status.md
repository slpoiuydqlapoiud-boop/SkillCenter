# M5.3-D 多实例指标与外部告警适配状态

日期：2026-08-18

## 本阶段结论

M5.3-D 的编码任务已完成。平台现在具备可替换的增量指标存储契约、Redis 多实例聚合适配器、告警状态边沿通知和并发/容量回归门禁；默认开发环境仍使用本地 JSON 与空通知实现。

## 已交付

- `OperationsMetricsStore` 增加桶级 `merge` 和 `sharedReads` 契约，JSON 存储保留原子替换并支持增量合并。
- Redis 存储按时间桶使用 Hash 和索引集合，Lua 脚本原子更新计数、延迟直方图、安全事件和最大延迟，并设置保留 TTL。
- 仅当 `skill-center.operations.metrics-storage=redis` 时选择 Redis；默认配置不连接 Redis。
- `OperationsAlertNotificationSink`、空实现和 HTTP Webhook 适配器，通知只发送聚合告警字段。
- 告警仅在 `ACTIVE`/`RESOLVED` 状态转换时通知，重复管理端轮询不会重复外发；通知失败不影响告警查询。
- 提供 Prometheus 抓取模板、告警规则、Alertmanager 路由和 Grafana 看板模板，支持标准 `Authorization: Bearer` 抓取。
- RC 门禁覆盖 JSON 合并、共享实例快照、8 线程并发聚合、20,000 事件容量回归、告警去重和 Webhook 脱敏。

## 配置示例

```yaml
skill-center:
  operations:
    metrics-storage: redis
    redis:
      key: skill-center:operations:metrics
      ttl-seconds: 3660
    alerts:
      notification-url: https://alert-gateway.internal/hooks/skill-center
      notification-timeout-ms: 1500
```

## 当前边界

本阶段没有宣称真实 Redis、Prometheus Server、Grafana、Alertmanager 或部门消息平台已经部署并连通。生产启用 Redis 前必须完成连接凭据、网络白名单、容量和故障切换评审；外部 Webhook URL 只能由受控配置提供，不接受用户请求参数。

部署模板位于 [`deploy/observability`](../../deploy/observability/README.md)。
