# M4.1 Distribution and Installation Telemetry Status

Date: 2026-08-17

M4.1 extends the M3 governance loop with a real local distribution path:

`published version -> short-lived authorization -> ZIP/CLI response -> client event -> installation status`

## Delivered

- One-time distribution authorization with a 15-minute TTL; only a SHA-256 token digest is persisted.
- Existing `POST /api/v1/skills/{skillId}/installations` remains compatible and now returns both the original manifest fields and:
  - `manifest`
  - `installationId`
  - `authorization` (`tokenId`, plaintext token for the client, expiry, method, download URL)
  - `cliCommand`
- Explicit authorization exchange: `POST /api/v1/distribution/authorizations/{tokenId}/consume`.
- Local published ZIP delivery: `GET /api/v1/distribution/artifacts/{skillId}/{version}?token=...`.
  - Validates Skill/version, published state, file type, single-use authorization, and SHA-256 response header.
  - Replays and expired/revoked authorizations return `DISTRIBUTION_AUTHORIZATION_INVALID`.
- Installation detail: `GET /api/v1/installations/{installationId}` with owner/role visibility rules.
- Installation batch events: `POST /api/v1/events/installations/batch`.
  - Supports partial success, `requested -> installed/failed/removed`, per-event results, and duplicate event IDs.
- Invocation batch events: `POST /api/v1/events/invocations/batch`.
  - Supports partial success, duplicate event IDs, and `EVENT_ID_CONFLICT` when the same ID carries different content.
- Frontend distribution modal with one-click/CLI/ZIP choices, client version, permission/hash/expiry display, CLI copy action, download action, and installation status polling.
- Frontend installation records show method, client, current status, installed time, and the last error code.
- New contracts:
  - `contracts/schemas/v1/event-batch.schema.json`
  - `contracts/schemas/v1/distribution-authorization.schema.json`

## Deliberate M4.1 boundaries

- Local JSON and local ZIP files remain the runtime adapters; object storage, SSO/JWT, message queues, and analytics warehouse are not claimed as production-ready.
- Installation event dedupe is process-local for the current event service; production migration must move the event receipt index into durable storage.
- Statistics range filters, version adoption, latency/error dashboards, and the management dashboard were delivered in [M4.2](M4.2-analytics-aggregation-status.md). Durable analytics storage, export files, deprecation/withdrawal impact, and notification center remain M4.3/follow-up work.
- No online Skill authoring or editing is introduced; all Skill content still originates from local ZIP upload.
