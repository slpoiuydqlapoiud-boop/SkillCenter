# M4.2 Analytics Aggregation Status

Date: 2026-08-17

M4.2 extends the M4.1 event ingestion path with range-based analytics and a management dashboard that uses the same backend aggregation contract.

## Delivered

- `GET /api/v1/analytics/overview` now supports:
  - `range=7d|30d|90d|custom` (default `7d`)
  - inclusive Beijing-time `from`/`to` dates for `custom`, capped at 90 days
  - optional `skillId`, `teamId`, and `clientType` filters
- Statistics use `Asia/Shanghai` natural days and return zero-filled dates for the complete requested range.
- Response keeps the legacy `kpis`, `series`, and `topSkills` fields and adds:
  - active users/teams, current installations, installation success rate
  - version adoption percentages
  - error-code breakdown
  - latency sample count, p50, p95, and max
  - process-local accepted/duplicate/rejected quality counts and backfill indicator
- Role scope is enforced server-side using the existing local actor headers:
  - admins/reviewers see global data
  - viewers see their own events/installations
  - maintainers see Skill records whose owner/team matches the actor ID
- Invocation ingestion now keeps a bounded, payload-free receipt summary for current-process data quality.
- Analytics dashboard now supports range selection, custom dates, Skill/team/client filters, extended KPI cards, version adoption, error/latency panels, and local-runtime quality copy.
- Custom range validation prevents incomplete, reversed, or over-90-day requests from reaching the API.

## Deliberate M4.2 boundaries

- Event and receipt summaries remain process-local; a restart loses invocation history and quality counters. Production migration must move event receipts and invocation detail to durable storage or an analytics warehouse.
- Installation conversion uses persisted installation status/request timestamps because installation event detail is not durable in M4.1.
- Version deprecation/withdrawal impact controls and personal-center data are delivered in [M4.3](M4.3-lifecycle-personal-center-status.md). Export files, notification center, and durable analytics storage remain follow-up work.
- No online Skill authoring or editing was introduced; all Skill content still originates from local ZIP upload.
