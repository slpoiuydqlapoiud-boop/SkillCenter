# M5.3-C 运行韧性与发布门禁状态

日期：2026-08-18

## 本阶段结论

M5.3-C 已完成。本地环境现在具备可恢复的聚合指标、受保护的 Prometheus 兼容输出、内部阈值告警和 RC 自动门禁，同时明确保留 Redis、集中式监控和外部通知的替换边界。

## 已交付

- `OperationsMetricsStore` 存储抽象和 JSON 文件实现。
- 最近 60 分钟指标桶启动恢复；文件使用临时文件加原子替换写入。
- 指标文件缺失不影响启动；损坏或不可读时健康状态为 `DEGRADED`，不暴露文件路径。
- `GET /internal/metrics` Prometheus 文本接口。
- `X-Metrics-Token` 校验：未配置 Token 时 404，缺失/错误 Token 时 401，正确 Token 时返回固定聚合指标。
- P95 延迟、5xx 错误率、安全事件计数三类阈值规则。
- `GET /api/v1/admin/operations/alerts?window=5m|15m|60m` 管理员告警接口。
- 运行监控页展示告警规则、当前值/阈值、active/resolved 状态和指标持久化健康状态。
- RC 门禁覆盖恢复、Prometheus 脱敏、告警状态转换、API 权限和 Spring 冒烟。

## 默认配置

```yaml
skill-center:
  operations:
    metrics-storage: ./data/operations/metrics.json
    metrics-token: ""
    alerts:
      p95-latency-ms: 1000
      server-error-rate: 0.05
      minimum-requests: 10
      security-event-count: 10
```

测试通过 `skill-center.operations.metrics-storage=memory` 隔离本地文件。

## 当前边界

本阶段不引入 Redis、Prometheus Server、Grafana、Alertmanager、SSO 或外部消息渠道。多实例共享需要实现 `OperationsMetricsStore` 的集中式适配器；外部告警需要接入独立的通知 Sink。当前告警状态为进程内状态，重启后会基于恢复的指标重新评估。
