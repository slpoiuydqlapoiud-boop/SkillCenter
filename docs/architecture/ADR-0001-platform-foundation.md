# ADR-0001：Skill Center 一期技术底座（历史企业级基线）

> 当前部门版默认部署以 [ADR-0002](./ADR-0002-department-windows-mysql-platform.md) 为准。本 ADR 中的 PostgreSQL、Redis、OpenSearch、消息、对象存储和多环境/企业级安全要求不再是部门版启动前置条件。

- 状态：M0 已接受
- 日期：2026-08-12
- 决策范围：一期管理、审核、分发和统计平台

## 决策

采用模块化服务架构，按业务域划分边界；M1 可以模块化单体起步，但上传校验、制品下载和事件接入必须保持独立部署接口，便于按容量单独扩展。

建议技术栈如下：

| 层次 | 选择 | 理由 |
| --- | --- | --- |
| Web | TypeScript、Vue 3、Vite | 适合桌面管理后台，组件生态成熟，便于权限路由和数据看板。 |
| 核心 API | Java 21、Spring Boot 3 | 适合企业 SSO、审计、事务和长期维护。 |
| 校验 Worker | Python 3.12 | 便于 ZIP、文件、依赖和内容扫描适配；通过队列与核心 API 解耦。 |
| 元数据 | PostgreSQL 16 兼容数据库 | 保存用户映射、Skill、版本、审核、权限和任务状态。 |
| 缓存 | Redis 7 兼容服务 | 保存短期授权、幂等键、限流状态和热点缓存，不作为事实源。 |
| 搜索 | OpenSearch 2 兼容服务 | 提供权限感知全文检索、筛选和聚合。 |
| 消息 | Kafka 3 兼容服务 | 承载上传任务、状态通知和安装/调用事件；Schema 版本化。 |
| 制品 | S3 兼容对象存储 | 保存隔离区和不可变发布区制品，支持哈希巡检和短期签名下载。 |
| 接口 | REST/JSON + JSON Schema 2020-12 | 便于 Web、客户端、网关和测试共用契约。 |
| 可观测性 | OpenTelemetry 接口 | 指标、日志和追踪接入部门现有监控平台。 |

若部门标准基础设施提供等价托管能力，应替换具体产品但保留接口语义和验收指标；替换需新增 ADR，不修改本 ADR 的业务边界。

## 模块边界

- `web`：市场、个人中心、审核和治理页面，不直接访问存储。
- `core-api`：身份、授权、Skill、版本、审核、分类、通知和审计事务。
- `validator-worker`：只读取隔离制品，生成不可变校验报告，不直接发布。
- `distribution`：签发一次性安装授权、安装清单和短期下载地址。
- `event-ingestion`：机器身份鉴权、白名单校验、幂等去重和入队。
- `analytics`：按北京时间聚合，仅向授权范围返回明细或汇总。

## 安全约束

- 生产部署在部门认可的内网环境，所有连接使用 TLS。
- 密钥只通过企业密钥系统引用，不进入配置文件、日志或事件。
- 发布制品内容不可变；治理元数据变化不能改写 ZIP。
- 搜索和统计在查询时执行二次授权，不能只依赖索引过滤。

## 环境

建立开发、测试、预生产和生产四套隔离环境。测试和预生产使用脱敏或合成数据；生产凭据、对象存储桶、数据库和消息主题不得复用。

## 不选择

- 不在一期采用微服务全面拆分，以免增加部署和分布式事务成本。
- 不以搜索索引、Redis 或统计汇总作为权限或版本事实源。
- 不在 M0 固化华为内部具体 SSO、扫描和监控产品名称，由适配器和下一阶段对接记录承接。
